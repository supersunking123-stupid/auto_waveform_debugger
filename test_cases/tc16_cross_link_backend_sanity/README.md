# Test Case 16: Cross-Link Backend Sanity Tests

## Phase 1: Backend Sanity

This test case validates the backend infrastructure before running cross-link tests.

## Test Assets

- RTL DB: `test_cases/rtl_trace.db` (generated by `test_cases/make_fixture.sh`)
- FSDB: `test_cases/wave.fsdb` (generated by `test_cases/make_fixture.sh`)
- Binaries:
  - `standalone_trace/build/rtl_trace`
  - `waveform_explorer/build/wave_agent_cli`

## Tests

### Test 1.1: Exact-edge waveform check

Validates waveform backend can find exact edges.

**Signal:** `top.hs_mon.clk`
**Time:** `175000`

Expected:
- `find_edge(..., posedge, 175000, backward)` → `175000`
- `get_value_at_time(..., 10009999)` → `"0"`
- `get_value_at_time(..., 175000)` → `"1"`

### Test 1.2: Structural trace sanity

Validates rtl_trace backend returns valid structural data.

**Signal:** `top.hs_mon.clk`
**Mode:** `drivers`

Expected:
- `status` = `success`
- Contains `target`, `mode`, `summary`, `endpoints`

### Test 1.3: FSDB signal-info sanity

Validates waveform signal metadata lookup.

**Signal:** `top.hs_mon.clk`

Expected:
- `status` = `success`
- Contains `path`, `width`, `type`, `timescale`

### Test 1.4: Fixture self-check

Validates the fixture constants in `test_cases/cross_link_common.py`.

Expected:
- `ready_in`, `valid_in` and `last_in` all fall at `175000`
- `ready_in` transitions are exactly `(2005000, "0")` and `(3005000, "1")` in the stall window

## Known Constraints

- Fixture simulation ends at `4000000` ps; reference posedge is `175000` ps (see `test_cases/cross_link_common.py`)
- Known-good clock edge: `top.hs_mon.clk @ 175000`
